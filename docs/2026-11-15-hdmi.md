# HDMI / DE352 / TCON3: confirmed F1 regression and vendor source trace

## Working and broken controls

Stock vendor 6.6.98 hardware image displays a Linux login console over HDMI. F1 (vendor 6.6.98 kernel, **hybrid 0.2.7 DTB**) boots Debian with USB Ethernet/SSH and root, **but HDMI retains the firmware splash**. Its Linux `dmesg` around 1 second contains:

```text
[drm] sunxi-hdmi: [error] check point match is err or null
[drm] sunxi-hdmi: [error] sunxi hdmi init core failed!!!
[drm] sunxi-hdmi: [error] hdmi devices bind failed!!!!!
sunxi-drm: failed to bind 5520000.hdmi0: -1
sunxi_drm_bind fail ret = -1
```

These are real driver failures. **Splash visibility cannot determine whether Linux runs.** Root/SSH do not imply HDMI success.

## Source-level root match (confirmed)

In pinned [vendor `drivers/drm/sunxi_device/sunxi_hdmi.c`](https://github.com/alexcaoys/allwinner-bsp/blob/656a550c826787e7e72fae58ca793df9e0988ac8/drivers/drm/sunxi_device/sunxi_hdmi.c), function `sunxi_hdmi_init` at ~1030:

```c
static const struct of_device_id hdmi_plat_match[] = {
    { .compatible = "arm,sun8iw20p1", .data = &sun8i_hdmi },
    { .compatible = "arm,sun50iw9p1", .data = &sun50i_hdmi },
    { .compatible = "arm,sun55iw3p1", .data = &sun55i_hdmi },
    { .compatible = "arm,sun60iw2p1", .data = &sun60i_hdmi },
    { },
};
...
match = of_match_node(hdmi_plat_match, root_node);
if (IS_ERR_OR_NULL(match)) return -1;
```

Hybrid 0.2.7 compiled root `"xunlong,orangepi-zero3w", "allwinner,sun60i-a733"` lacks `"arm,sun60iw2p1"`, so the root match fails. `drivers/drm/sunxi_drm_hdmi.c` `_sunxi_hdmi_init_drv` calls `sunxi_hdmi_init` at ~3328 and reports the core initialization error at 3330; final bind failure is downstream at ~3488.

This is a **source-confirmed reason for F1 HDMI core failure**. The unmodified vendor Zero 3W source oddly declares `"xunlong,orangepi-4-pro", "arm,sun60iw2p1"`. The new isolated 6.6.98 identity build corrects board identity while retaining `arm,sun60iw2p1`. Build PASS only, not hardware tested.

## Other HDMI dependency chain

- `sunxi_drm_drv.c`, `sunxi_drm_hdmi.c`, `sunxi_device/sunxi_hdmi.c`, `sunxi_device/hardware/lowlevel_hdmi20/` and `phy_snps.c`.
- A733 display engine DE352 at `0x05000000`, TCON3 `0x05730000`, HDMI controller `0x05520000`; Synopsys PHY and HPD/EDID.
- DCDC2 and CLDO2 from AXP8191 provide HDMI rails.
- DTB HDMI params: `hdmi_clock_source=0`, `hdmi_resistor_select=1`, `hdmi_ddc_index=20`, HDCP1x/2x=1, CEC=1, `snps_phy` 20 numeric cells.
- `sunxi_hdmi_init` runs board init and then `dw_hdmi_init`. In `phy_snps.c`, `snps_phy_init` matches `plat_id`, then parses `snps_phy` table; this does **not** prove a PHY table defect. Do not tune PHY values until root match works.
- G1 only sees /chosen, /memory and DE IOVA additions from U-Boot, not HDMI node changes. F1's HDMI error is a driver-root match problem, not a missing HDMI node.

## Acceptance test, separate from kernel boot

From actual Linux `dmesg`, check absence of root platform-match error, success of HDMI DRM bind, registration of connector/CRTC/plane, EDID/HPD and active modeset. Confirm physical Linux console output (not static bootloader frame). Working framebuffer HDMI is **not** proof of PowerVR GPU acceleration or unmodified Mesa. Do not ship 6.18 as HDMI-capable based only on compiled drivers.
