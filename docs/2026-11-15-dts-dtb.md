# Zero 3W DTS and DTB: compiled, live and vendor references

## Three distinct trees

1. **Vendor 6.6.98 source:** `arch/arm64/boot/dts/allwinner/sun60i-a733-orangepi-zero3w.dts` in pinned `linux-orangepi`. Unexpected root `compatible = "xunlong,orangepi-4-pro", "arm,sun60iw2p1";`. File name and board-compatible conflict. It includes `sun60iw2p1.dtsi` and A733 board hardware nodes.
2. **Hybrid 6.18.19 0.2.7 compiled DTB:** SHA256 `5c9cd102215183cc56150aab2ce331216bea26d80741cdfc1fb0d95f5818e7b9`, 171,337 B, root `xunlong,orangepi-zero3w`, `allwinner,sun60i-a733`, **missing** vendor `arm,sun60iw2p1`.
3. **F1 runtime DTB:** same hybrid source modified by U-Boot, SHA256 `5a8db361113336b27f428520fb5b00e80c9a16ae9dd755743dc0d65ed9376db9`, FDT `totalsize` 589,952 B. Most size difference is reserve capacity, not new hardware nodes.

## Root compatible mistake is a concrete HDMI regression

Vendor `sunxi_hdmi_init()` calls `of_match_node(hdmi_plat_match, root_node)`. Table contains `"arm,sun60iw2p1"`. The hybrid DTS omitted this fallback, and F1's HDMI core failed before DRM bound. Proposed **identity-only** correction for official 6.6.98:

```dts
compatible = "xunlong,orangepi-zero3w", "arm,sun60iw2p1";
```

This preserves vendor-SoC matches and removes erroneous Orange Pi 4 Pro board identifier. **The rebuild has compiled but not been hardware tested.** A separate 6.18 hybrid root fallback correction requires its own test and cannot be equated with a 6.6.98 pass.

## G1 compiled vs F1 live DTB

Only three selected nodes differ:

| Node | Change | Significance |
| --- | --- | --- |
| `/chosen` | bootargs and relocated initrd | U-Boot injection |
| `/memory@40000000` | 512 MiB -> 1 GiB | U-Boot RAM fixup verified |
| `/soc@3000000/de@5000000` | `sunxi-iova-premap` | Display memory premap |
 
G1 parser defect: its binary `reg` property was displayed as characters rather than 32-bit BE cells. Trust independently decoded DTS and FDT binary audit, not corrupted `reg` display.

## Hardware wiring from vendor DTS

- AXP8191 at `pmu@36`, AXP515 at `pmu@34`, both on R-TWI0 controller `twi@7083000`, pins PL0/PL1.
- MMC0 `sdmmc@4020000`, v5p3x controller, SD PF0–PF5 and card-detect PF6; `vmmc`, `vqmmc33sw`, `vdmmc33sw` -> AXP8191 DC1SW2. `vqmmc18sw`, `vdmmc18sw` -> CLDO5.
- Red status LED `/leds/led-0` active-high PL7 with `linux,default-trigger = "heartbeat"`.
- UART0 DT pinctrl `pins = "", ""` despite boot-debug `sys_config.fex` claiming PB9/PB10. PB9/10 also appear in disabled TWI8. No validated Linux UART diagnostic connection.
- HDMI controller at `0x05520000`, display engine DE352 at `0x05000000`, TCON3 at `0x05730000`; HDMI rails DCDC2 and CLDO2, plus `snps_phy` tuning table.
- `memory@40000000` static 512MiB is same in both vendor and hybrid DTBs; actual RAM fixed up by U-Boot.
- `/reserved-memory/bl31` covers `0x48000000..0x49000000`, preserve secure firmware allocations.
- DSI `graph_endpoint`/`graph_child_address` warnings on decompile exist; not a proven HDMI failure.

## Board facts vs software validation

F1 proves hybrid DTB enables vendor Linux 6.6.98 full userspace/storage/USB networking, **not** working HDMI or all peripheral drivers. F2 6.18 with vendor DTB failing to reach proven userspace does **not** prove the vendor DTB invalid under 6.18; cross-version bindings differ.

Use vendor DTS as **hardware source** and adapt the minimum necessary binding differences to each kernel. Audit final compiled DTB, not only textual source; preserve fallback `arm,sun60iw2p1` for BSP HDMI where required. Avoid inferring SoC safety from generic T736 demo DTS.
