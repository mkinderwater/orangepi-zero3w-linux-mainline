# PMIC, R-TWI, regulators, MMC, DDR and RTC

## Exact vendor A733 / Zero 3W dependency chain

`CONFIG_AW_SUN60IW2_CCU=y` and `CONFIG_AW_PINCTRL_SUN60IW2=y` and `CONFIG_AW_PINCTRL_SUN60IW2_R=y` -> `CONFIG_AW_DMA=y` -> `CONFIG_AW_TWI=y` -> `CONFIG_AW_MFD_AXP2101=y`, `CONFIG_AW_MFD_AXP2101_I2C=y`, `CONFIG_AW_REGULATOR_AXP2101=y` -> AXP8191 at `0x36` and AXP515 at `0x34` on R-TWI0 PL0/PL1 -> regulators -> `CONFIG_AW_MMC=y` / MMC0. UART `CONFIG_AW_UART_NG=y`. All these were **verified enabled in actual hybrid 0.2.7 build/.config**, not just a defconfig.

Pinned BSP I2C OF match explicitly supports both `x-powers,axp8191` and `x-powers,axp515`. `axp2101.c` has AXP8191 regmap, IRQ chip and MFD child `axp2101-regulator`; `axp2101-regulator.c` registers AXP8191 DCDC1–9, DC1SW1/2, CLDO1–5 and more. AXP515 is a second controller, not interchangeable with AXP8191.

## Compiled hybrid 0.2.7 MMC verified

- `CONFIG_AW_MMC=y`, compiler object `build/bsp/drivers/mmc/sunxi-mmc.o`, `sunxi-mmc-v5p3x.o` and symbol `sunxi_mmc_probe` in `vmlinux`.
- Executable object strings contain `allwinner,sunxi-mmc-v5p3x`, same as compiled `sdmmc@4020000` DTB.
- Regulator phandles resolve: `vmmc`, `vqmmc33sw`, `vdmmc33sw` to DC1SW2; `vqmmc18sw` and `vdmmc18sw` to CLDO5.
- These checks **prove build/link/DTB compatibility**, not runtime MMC enumeration under 6.18.
- BSP `sunxi_mmc_regulator_get_supply` logs missing supplies but returns 0, potentially obscuring probe deferral. Do not remove `vmmc-supply` to mask PMIC failure.
- Independent [nickyg666 6.18 bring-up](https://github.com/nickyg666/orangepi-zero3w-mainline) reported absent `AW_TWI`, regulator deferral and MMC voltage issues. Our hybrid already has `AW_TWI=y`, so that specific external fix does **not** apply unchanged.

## Physical F1 PMIC / bus evidence

Vendor 6.6.98 + hybrid DTB initializes AXP8191 at `0x36`; SD MMC0 works and `/dev/mmcblk0p1` is root. F1 kernel log additionally reports:

```text
sunxi:twi-7083000.twi: Timeout when sending 9th SCL clk
axp20x-i2c 13-0034: Failed to set masks in 0x40: -22
axp20x-i2c: probe of 13-0034 failed with error -22
```

Thus AXP515 at `0x34` has a genuine probe error, even though AXP8191/SD boot succeed. This does **not** prove AXP515 physically absent; audit I2C timing/interrupt mask path and board variants before altering voltages.

Vendor F1 log also contains `sunxi:ccu_ddr-2002000.clk_ddr: failed to find dram_clk` and a HYM8563 RTC I2C timeout. The Zero 3W has no battery-backed RTC available for reliable pre-network timestamps in the tested setup; an RTC DT node is not proof the external part is populated. Don't delete it without hardware evidence. Some virtual DC1SW1/DC1SW2 consumers report dummy regulators while physical MMC still works; virtual consumer is not necessarily failed physical rail.

## Earlier experimental 6.18 limited PMIC patch

M2r/M2cb standalone AXP8191 driver exposed only DCDC1, DC1SW2 and CLDO5, with five writable registers: `0x10` (DCDC1 enable), `0x11` (DC1SW2 enable), `0x12` (DCDC1 voltage), `0x21` (CLDO5 enable), `0x33` (CLDO5 voltage). That patch compiled, but has **no direct runtime rail safety test**. It must not silently replace the full BSP regulator in a build. See [original PMIC note](pmic-mmc-and-i2c.md) and [experimental patch](../patches/experimental/axp8191-m2cb.patch).

## Safe changes

Two isolated hypotheses per batch; preserve original PMIC write behavior unless validating individual writes against datasheets and hardware. Do not confuse proof of root mount (6.6 kernel) with proof of 6.18 PMIC probe. Voltage-switching correctness, USB-C power, display rails and DVFS remain unresolved under 6.18.
