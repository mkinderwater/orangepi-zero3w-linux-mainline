## DTB differences and conclusion

Vendor F1 kernel with hybrid 0.2.7 DTB **does boot**, so many core hardware bindings are functional. Its HDMI fails because the hybrid root drops vendor `arm,sun60iw2p1`. F2 (6.18 Image + vendor DTB, no initrd) showed different LED behavior but no userspace proof. K2 no-initrd also failed to show proof. Thus current 6.18 blockage could be in entry, early init, incompatible subsystem, root discovery, kernel logging or other cause; a solid LED/splash alone cannot identify the stage.

## Restart plan after validated 6.6.98

1. Freeze fully tested 6.6.98 vendor kernel and corrected Zero 3W DTS in the same repository with exact source SHA/patches.
2. Audit 6.18 ABI integration and core boot prerequisites against the proven 6.6 source, **two isolated hypotheses per test batch**.
3. Record actual U-Boot handoff and independent earliest Linux signal (serial UART physically validated, or safe GPIO marker with separately proven mux). `printk` alone is insufficient absent working console.
4. Only then diagnose I2C/PMIC, MMC/root; then native DRM/HDMI; then PowerVR acceleration.
5. Do not apply a generic DTS swap, copy demo T736 configurations, arbitrarily change memory nodes, disable MMC supply, or edit PMIC rail voltages to clear a warning.
